# Keybound Pilot

作者: Roxyz0501。新規独立Dalamudプラグイン。バージョン 1.0.5.0、API 15。

キーバウンド・ブロウラーの出題を読み、Windows `SendInput` のスキャンコードでキーの押下・解放を送ります。入力間隔は下限・上限の範囲から1キーごとに抽選します。設定値は20〜5000ms、初期値80〜150msです。同値なら固定間隔になります。

## 1.0.5.0 の修正

定期的に文字が隠れる状態では、一度も表示を確認していない出題を入力候補から除外します。バリア強化・詠唱優先より先に、この条件を適用します。

- 出題枠の存在だけでなく、実際の文字ノードと親の表示・透明度・縮尺を確認します。画面の敵IDと読みがデータ配列の現在の出題と一致してから「表示済み」にします。
- 一度表示された同じ出題は、再び隠れても入力を続けられます。表示枠の並び替えで履歴を取り違えません。
- 同じ敵でも出題が変われば未表示扱いに戻します。敵の消失・フェーズの出題画面消失・退出時に不要な履歴を破棄し、最大20対象だけを保持します。
- 対象の消失と文字の一時非表示を分離しました。対象自体が消えた場合は前版のBackspace削除・次の対象への移行を行います。
- 診断ログに敵IDごとの文字表示判定を差分追加しました。入力文字列や新たなゲームテキストは保存しません。

以前のログには出題枠の表示状態がありましたが、その中の文字ノードの表示状態はありません。過去ログだけで個々の出題の初回表示時刻は確定できません。既存ログとローカルUI構造を調べたうえで文字表示の確認を追加しています。改修後の実ゲーム動作は未検証です。

## 1.0.4.0 の修正

- フェーズ1〜3の切替、入力欄の一時無効化、フォーカス喪失では停止せず待機します。結果画面またはコンテンツ退出時に自動停止します。フォーカスは最大3回の試行後、2秒間待って再取得します。他の入力欄・別アプリが使用中は送信を待ちます。
- ▶ 開始／再開、Ⅱ 一時停止、■ 停止の記号ボタンに変更しました。3秒の開始待ちをなくし、開始時にもプラグイン画面を開いたままにします。キーごとの設定間隔と入力欄・IMEの準備待ちは維持します。
- 次の入力対象は「バリア強化の支援出題 → 詠唱中の敵 → 通常の敵」の順です。支援出題は表示中の種別2を判別し、文章の長さだけでは選びません。詠唱中の敵同士は進行度を優先します。
- 入力途中に対象が消えたら、残った文字を実際のBackspace操作で削除します。未確定文字と確定済み文字がなくなったことを確認してから次の対象に進みます。削除中に同じ対象が再表示されても、古い入力を再開しません。
- 「ゔ」を含む回答は、IME確定前にF6を一度送ってひらがなに変換します。「ゔ／ヴ」と濁点のUnicode表記差で誤停止しない照合に変更しました。別の読みや未変換の英字は引き続き送信しません。診断には照合結果の分類だけを記録します。
- 動的な出題に必要な文字をフォントへ追加し、4種類のCJKフォントが準備できてから切り替えます。準備中・失敗時は英語で案内します。操作ボタンの記号は図形で描画します。

IMEのF6によるひらがな変換は [Microsoft公式のキー操作](https://support.microsoft.com/ja-jp/windows/hardware/input-devices/microsoft-japanese-ime) に基づきます。表記差が報告された停止の原因である可能性はありますが、確定文字本文は保存していないため断定はしていません。改修後のゲーム内動作は未検証です。

## 入力方式

日本語の読み仮名をローマ字キー列へ変換し、IMEの変換確定とゲームへの回答送信を分離します。小書き文字・促音・長音・「ん」、波線「~」「～」「〜」に対応します。IME状態の取得・設定ができない場合や、確定した読みが一致しない場合は停止します。

日本語の技名「動体感知ジャマー」は、同じ敵の詠唱が90%以上まで進んだあと消える変化を発動の目安にし、そこから4秒間待機します。早い中断・敵の消失では発動扱いにしません。サーバーの発動通知ではなく表示情報からの推定です。4秒はユーザー指定で、他言語の技名や他の入力禁止技は未対応です。

## 利用方法

共有カスタムリポジトリ:
`https://raw.githubusercontent.com/Roxyz0501/DalamudPluginRepo/main/repo.json`

既存の導入済み環境ではDalamudのプラグイン更新から更新してください。個別配布は [GitHub Releases](https://github.com/Roxyz0501/KeyboundPilot/releases)。

1. `/keyboundpilot` →「設定」で入力間隔と「ゲーム開始時に自動実行」を指定します。自動実行は既定で有効です。
2. ゲームの出題と入力欄が使用可能になると自動開始します。手動開始は ▶、一時停止も ▶ で再開できます。画面を閉じる操作は不要です。
3. Ⅱ で進捗を保ったまま一時停止します。■、Esc、`/keyboundpilot stop` で終了します。手動停止やエラー停止後は勝手に再開せず、▶ で開始し直します。

日本語IMEの状態・確定した読みを確認できない場合は、その旨を表示して停止します。IMEの設定変更は入力開始時に行い、停止時に未確定文字がなければ元へ戻します。未確定文字が残る場合は、それを勝手に確定・削除する操作を避け、IMEの復元を行いません。新しいMicrosoft IMEなどでは状態変更APIが利用できない場合があり、その環境での入力成功は未検証です。

## 診断ログ

コンテンツ内では自動入力停止中も記録します。「診断ログ」タブで開始・停止・保存先コピー・場面の目印を操作できます。`/keyboundpilot log start`、`log stop`、`mark block`、`mark cast` も利用できます。

保存先は通常 `pluginConfigs/KeyboundPilot/diagnostics/YYYY-MM-DD/ktg-<session>.jsonl`（日本時間）です。100msごとに専用ゲームデータを確認し、変化した整数・出題・読み・技名・UI区分だけ保存します。IMEの利用可否・入力モード・変換中かどうかとジャマー判定も記録します。

チャット、プレイヤー名、入力欄の文字列、生のキー、認証情報は記録しません。ひらがなの一致確認には入力欄をメモリ上で読みますが、文字列を保存しません。ログを自動送信・削除しません。既存1000ファイルの上限は維持します。最大64KiBのバッファで2秒ごと・目印・退出・終了時に追記し、結果不明の書込失敗は再送せず停止します。

`python tools/Analyze-Logs.py <ログファイルまたはフォルダー>` で旧版・新版の差分ログを集計できます。ログ本文を公開リポジトリや配布ZIPへ含めないでください。

## 動作と制限

キーは少なくとも10ms押下して次の更新で解放します。遅れたフレームの連打による追い付きは行いません。IME確定・フォーカス待ち・フレーム遅延では設定上限より長い間隔になる場合があります。貼り付け、テキスト欄への直接書き込み、回答コールバック、直接のサーバーパケット送信は使用しません。ゲーム内APIの変更操作は専用欄のフォーカス取得に限ります。

自動入力は対象コンテンツ内に限定します。自動開始が有効な場合はゲーム開始時に一度だけ実行し、無効なら開始ボタンを使います。参加・移動・再申請・報酬操作の自動化は含みません。Windowsの前面PIDを送信直前にも確認しますが、OS配信までのフォーカス変更競合を完全には排除できません。同じ出題が送信後も3秒以上変化しなければ停止します。

設定は変更時のみ60秒ごとに保存し、ログアウト・通常終了・無効化時にフラッシュします。正常バックアップ3世代と変更履歴を保持します。外部API・業務DBの読み書きはありません。日本語・English・Deutsch・Français・한국어・简体中文・繁體中文のUIがあります。
