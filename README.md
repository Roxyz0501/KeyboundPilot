# Keybound Pilot — 文字自動入力の公開プレビュー

作者: Roxyz0501。新規独立Dalamudプラグイン。バージョン 1.0.1.0、API 15。

キーバウンド・ブロウラーで表示された英数字・ローマ字の出題を取得し、Windows `SendInput` のスキャンコードによる **KEYDOWN / KEYUP** を送る試作版です。テキスト欄の値変更、ゲーム側コールバックの呼び出し、貼り付け、`WM_CHAR`、サーバーパケットの直接送信は行いません。

**実ゲーム未検証です。実際の出題取得・フォーカス判定・キー認識の成功はまだ確認できていません。** 既存SDKとインストール済みゲームファイルで検証した公開プレビューです。既存のプラグインDLL・ユーザー設定は変更していません。

## 1.0.1.0：まず実際のプレイログで調査

**ユーザー環境で文字入力が動作しないとの報告があり、調査中です。自動入力が直ったことはまだ確認していません。詠唱優先・入力禁止の自動判定も、実ログで条件を特定してから実装します。**

更新版では、コンテンツに入ると診断記録が自動で始まります。自動入力を開始する必要はありません。まず手動で1回プレイし、退出するか診断タブで記録を停止してください。

- `/keyboundpilot` → **診断ログ** タブで記録状態を確認できます。
- 「保存先をコピー」で実際のログ保存先をコピーできます。通常はDalamudの `pluginConfigs/KeyboundPilot/diagnostics/YYYY-MM-DD/ktg-<session>.jsonl` です（日付は日本時間）。
- 「入力禁止を見た時の目印」「詠唱を見た時の目印」で、その瞬間を任意に注記できます。ボタンのために入力フォーカスを外す必要がある場合は無理に押さず、そのままプレイして大丈夫です。
- 自動入力が停止していても、専用UIと専用配列の変化を100msごとに確認し、変化した部分だけ記録します。コンテンツ外では読み取りません。
- チャット、プレイヤー名、入力欄の文字列、生のキー入力、アカウントID、認証情報、メモリアドレスは記録しません。出題・読み・敵の技名、敵の一時ID、入力欄の表示／有効／フォーカス／文字数、UIの可視状態、未解釈の専用整数データが対象です。
- ログは外部へ自動送信しません。既存ログも自動削除しません。
- 上限は1回30分・8MiB、合計32MiB、既存ログ1000ファイルです。上限では停止し、再開は診断タブから明示操作します。
- 最大64KiBのメモリバッファにまとめ、2秒ごと／目印／退出／終了時に追記します。書込み結果が不明な失敗は自動再送せず停止します。
- 停止は `/keyboundpilot log stop`、再開は `/keyboundpilot log start` でも可能です。設定は次回プラグイン読み込み時に自動記録ONへ戻ります。
- ログ解析補助: `python tools/Analyze-Logs.py <diagnosticsフォルダー>`。解析はローカルのみです。未知フィールドの意味や入力禁止条件は推測で確定しません。

1.0.1.0には、確定用Enterの送信と、複製された先頭UI要素への依存をやめて専用配列から出題を読む修正も含みます。どちらも実ゲームで成功したとはまだ判断していません。

## 導入と操作

1. Dalamud設定の「試験的機能」→「カスタムプラグインリポジトリ」に、共有URL `https://raw.githubusercontent.com/Roxyz0501/DalamudPluginRepo/main/repo.json` を登録します。
2. プラグインインストーラーで **Keybound Pilot** を検索してインストールします。
3. `/keyboundpilot` で開き、「設定」で入力間隔の下限・上限を指定します。初期値は **80〜150ms**、許容値は20〜5000msです。
4. コンテンツ内で「表示文字を確認」を押して出題数を確認します。0件のままなら取得経路が未対応です。自動入力が動作済みとは判断しないでください。
5. 「開始（3秒後）」を押し、3秒以内にゲームの専用入力欄をクリックします。開始時にフォーカスが取れない場合も停止します。
6. 停止ボタン、`/keyboundpilot stop`、Escで停止します。ゲームが前面でなくなった場合、修飾キーを押した場合、入力欄のフォーカスを失った場合も停止します。

手動導入の場合は[GitHub Release](https://github.com/Roxyz0501/KeyboundPilot/releases/tag/v1.0.1.0)の `KeyboundPilot-1.0.1.0.zip` を開発用プラグインフォルダーに展開し、`KeyboundPilot.dll` を開発用プラグイン設定へ登録します。

現在のConfigは「設定」「言語設定」「支援」の順です。下限を上限より大きくした場合は上限も引き上げ、上限を下限より小さくした場合は下限も引き下げます。同値なら固定間隔になります。入力中の設定変更は一度停止します。

## 入力方法と制限

- 1文字ごとに上下限を含む範囲から均等に待ち時間を抽選します。キー押下の後、少なくとも10ms経過してから次のFramework更新で解放します。
- 次の押下予定は実際に送った時刻から計算します。処理落ちで連打による追い付きはしません。フレーム間隔・OS処理の遅延により実際の間隔が上限を超えることがあります。
- キー配列はゲーム前面ウィンドウのキーボードレイアウトで変換します。大文字表示は同じ物理英字キーとして送ります。Shift必須の記号・非ASCII文字・IME入力は今回未対応で、推測して送信しません。
- 対象は `TerritoryIntendedUse = 65` と可視の `KTGInput`、フォーカス中のTextInputコンポーネント7。出題はKTG専用NumberArray 161とStringArray 128を参照する仮実装です。ローカル実行ファイルの両UI更新処理から、最大20件・13整数／3文字列の配置を確認しました。未知フィールドは未解釈のままログに残し、戦闘判定には使用しません。実際のゲーム動作は未検証です。
- 自動入力用の出題取得は実行中だけ最大20Hz、キー送信直前にはその出題と入力フォーカスを再確認します。消えた出題は続けて入力しません。同じ文字列が複数同時にある場合は最初の出題を扱い、同じ出題が残っている限り再入力しません。
- 入力が終わっても出題が3秒以上残る場合は停止します。これはキーが認識されたことの保証ではありません。キー送信APIが失敗した場合、文字は自動再送しません。
- WindowsのSendInputは前面入力です。前面・PIDを直前確認しますが、確認とOS配信の間にフォーカスが切り替わる競合を完全には排除できません。
- 参加・移動・再申請・結果画面・報酬交換の自動化は今回含みません。起動時に自動実行しません。

## 保存・負荷

設定は変更がある場合のみ60秒ごとに保存し、ログアウト・通常終了・無効化時にフラッシュします。正常バックアップ3世代を保持し、破損時は有効な世代を復元します。通常の自動保存は連続3回失敗で停止します。生のキー入力履歴は保存しません。明示的に追加した診断機能はコンテンツ内で自動入力停止中も状態を記録します。外部API・業務DBへのアクセスはありません。

日本語・English・Deutsch・Français・한국어・简体中文・繁體中文のUIを用意しています。初回だけゲーム言語、Dalamud公開UI言語、英語の順で選び、選択を保存します。ランチャー設定を読む公開APIは使用していません。実ゲームの描画・フォント表示も今後の確認対象です。
