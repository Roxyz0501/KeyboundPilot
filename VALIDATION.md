# Validation — 1.0.2.0 / 2026-10-28 JST

- Read the user's local manual-play recording: 2,319 JSONL records, 2,317 usable snapshots, no invalid lines, 8,388,155 bytes, approximately 325.7 seconds. The old 8 MiB cap stopped recording; the end of the game is not present. Auto typing was stopped throughout, so this recording does not test SendInput success.
- All recorded readings were rejected by the old ASCII-only reader. The new pure conversion accepts all 116 distinct readings, including ASCII tilde, full-width tilde and wave dash. A tilde maps through the foreground keyboard layout with physical left Shift; only owned Shift is exempt from the modifier stop gate and both key and Shift are released. Ctrl/Alt/AltGr mappings remain rejected. Committed wave variants normalize before comparison. Explicit small-kana key sequences and n-apostrophe avoid ambiguous syllable boundaries.
- KTG input IsActive repeatedly changes from true to false after answers, while Enabled remains true. Automatic focus acquisition now uses the SDK's AtkInputManager.SetFocus on the dedicated component's collision node, at most three attempts, 250ms apart. No text-setting API or answer callback is used.
- The real log replay identifies two same-entity late-jammer cast disappearances at 240,738.1092ms and 323,865.5107ms. Enemy record field 7 is used as cast progress; string triple field 2 is the cast label. Late disappearance (>=90%) is an activation inference, not a server action event. Four seconds is explicitly user-selected, not a measured debuff duration. Early interruption and enemy disappearance do not trigger it. Detection only recognizes the observed Japanese jammer name; other prohibition mechanics are not verified.
- 69 offline checks plus 3 actual-log replay assertions pass (72 with the local log argument). Coverage includes physical-key scheduling, separate IME-confirm and answer Enter, rejection of unmatched committed Japanese, exact four-second pause/resume, no duplicate timer extension, early interruption/despawn, cast priority, partial-target loss, UI deltas, persistence, and diagnostic failure/limits. Tests send no actual keys or game input.
- Clean Release: zero warnings/errors. 53 UI keys x 7 languages; canonical trailing tabs byte-identical. In-game fonts, native focus acquisition, IME transitions and physical keyboard acceptance remain unverified after this change.
- IME preparation uses the game window's IMM context and requests hiragana/romaji mode. It does not install an IME or change keyboard layouts. Mode is checked before typing and committed text is compared before the game Enter. Composition length/flags only are logged; actual input text is transient in memory. A failed mode change stops. Mode restoration is attempted only with no remaining composition; cleanup does not submit or cancel residual user text.
