# Validation — 1.0.3.0 / 2026-10-28 JST

- Investigated the reported failure locally. The prior update applied broad focus-stop checks before arming and before the dedicated input was enabled. This could stop the session before focus acquisition and before any character was sent. No claim of live successful typing is made.
- Lifecycle gating now protects the three-second arming interval, then waits for disabled input instead of declaring focus lost. Foreground loss, Escape and modifiers still stop, including during arming. Another active text editor is protected; general focused HUD addons are no longer treated as competing text input.
- Focus acquisition activates the dedicated addon and sets its collision node through SDK focus methods. The final retry receives its full observation interval. No text is written and no answer callback is invoked. Installed native inspection confirmed the SetFocusNode wrapper dispatches the node to the input manager. Native focus/IME/keyboard behavior after this update remains unverified.
- AutoStart defaults true, including configurations that predate this property. It starts only once per content entry after an enabled input and a valid word appear, with game foreground and no competing UI. Manual/error stops remain stopped until the Resume button. Leaving the content resets eligibility. The checkbox is persisted through the existing changed-only save and backup path.
- Existing Japanese hiragana mode is preserved; the implementation does not impose a ROMAN flag on an already working IME. Composition verification, physical keys, wave symbols, cast priority, and the user-selected four-second jammer delay remain. Jammer activation is inferred from late cast disappearance, not a server action event.
- 89 offline checks pass, plus 3 local replay checks for startup timing and waiting across unavailable input. Tests include start-button capture, disabled input, auto-start suppression/re-entry, resume arming, third-attempt success/exhaustion, and old/new AutoStart configuration persistence. Tests send no actual keys. Captured gameplay records and detailed per-game statistics/timestamps are not included in this publication report.
- Clean Release: zero warnings/errors. 55 localization keys x 7 languages. Canonical trailing tabs retained byte-for-byte; in-game rendering remains unverified.
- Diagnostics add cached control-gate and focus-request state. No chat/player names/raw key or input text is logged; committed text comparison stays transient in memory. Existing 64 MiB/session, 256 MiB total, 120-minute and 1000-file limits, 64 KiB buffer, two-second flush, JST partitioning, no uncertain-append replay, and no upload/deletion are retained.
- Design bounds: one dedicated reader refresh per 50ms while typing or awaiting auto start; diagnostic sampling per 100ms; zero gameplay scans outside the content. UI reads cached state. No network/DB access in the plugin. Unchanged diagnostic state emits no record. Config fixture: 8 commits, 616 logical payload bytes, 539 backup bytes; actual SSD physical writes are not measured.
- Original icon and license/notices retained. ZIP excludes host DLLs, PDBs, captured logs and investigation tools. Publishing does not overwrite the installed DLL or production configuration.
